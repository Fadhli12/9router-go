### Fixed

- **Codex: `json_object` requests no longer fail with 502 when the JSON request lives only in the system prompt.** A Chat Completions request with `response_format: {"type":"json_object"}` maps to `text.format: json_object`, and system/developer text is hoisted into `instructions`. The ChatGPT Codex backend only checks `input` for the word "json", so these requests were rejected on every account with `Response input messages must contain the word 'json' in some form to use 'text.format' of type 'json_object'.` `ForwardCodex` now prepends a developer message (`Respond with a JSON object.`) when `text.format` is `json_object` and no input item mentions JSON. Scoped to `provider == "codex"`; `json_schema` and bodies without `text.format` are unchanged. Deliberate divergence: upstream decolua/9router `main` has no handling for this error.

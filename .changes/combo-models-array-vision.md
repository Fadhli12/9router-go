### fix(dashboard): GET /api/combos serves `models` as a JSON array

- **Wire shape** (`internal/handlers/dashboard/combos.go`, `combos_wire.go`): `GET /api/combos` now emits each combo's `models` as a JSON array instead of the JSON string the column holds. The top-level array and every other field (`kind`, `strategy`, `matchRules`, `customPrompt`, `autoMembers`, timestamps) are unchanged. Upstream parity: `decolua/9router` `main` commit `5ae63d22847e07042e235b40e1d926b65e509013`, `src/lib/db/repos/combosRepo.js` `rowToCombo` returns `models: parseJson(row.models, [])`.
- **Storage untouched**: `models.Combo.Models` stays a string and the `combos.models` column is unchanged (no schema change, SQLite and PostgreSQL alike). Only a response DTO overrides the field. Legacy object members (`{model, weight}`) pass through unchanged.
- **Corrupt rows**: an empty, invalid, or non-array stored value is served as `[]` with a warning log, matching upstream's `parseJson` fallback, so one bad row cannot break the Combos view.
- **Dashboard**: `web/src/api/client.ts` `Combo.models` is now `string | string[]`. The existing parsers (`getComboModels`, `MediaWebView`, `AnalyticsView`) already accept both shapes. The `svelte-check` ratchet stays at 0 errors.
- **Tests**: `TestGetCombosEmitsModelsAsArray` (`internal/handlers/dashboard/combos_wire_test.go`) fails on the base (six wire cases serve a string) and passes with the fix. `TestCombosEndpoints` and the integration assertions in `keys_test.go`, `combo_presets_test.go` and `smart_combo_routes_test.go` now decode `models` as an array.

### Fixed

- **Media Providers "Add Connection" never stored the API key** (elevenlabs et al.). `MediaProviderDetail.svelte` sent the key under the field name `key`, while `POST /api/connections` (`createConnectionRequest`) reads `apiKey` — the backend ignored the unknown field and created the row with `data: {}`, so every media request failed with `no API key found` even though the operator had pasted a valid key. The payload now sends `apiKey`, matching `CreateConnectionPayload` and the backend contract. Verified by `bun run build`, `make vet-svelte` (baseline 73 unchanged), `bun test src scripts` (855 pass), and `go test ./web/...`.

### Added

- **ElevenLabs TTS lane for `/v1/audio/speech`** (upstream parity: `open-sse/handlers/ttsProviders/elevenlabs.js`). The vendor API is not OpenAI-shaped — the voice id rides the URL path (`/v1/text-to-speech/{voice_id}`) and the body is `{text, model_id, voice_settings}` — so the generic OpenAI-compatible funnel posted an OpenAI body to a path ElevenLabs never serves and every request answered `404 {"detail":"Not Found"}`. A dedicated adapter now posts the vendor wire shape with the connection's `xi-api-key`, honoring model/voice conventions identical to upstream: `el/<model_id>/<voice_id>`, `el/<model_id>` + OpenAI `voice` field, or a bare voice id (default model `eleven_flash_v2_5`). Account rotation and per-connection failure locking follow the nvidia TTS lane's pattern. Verified with `go test ./internal/handlers/media/` (new table-driven tests pinning the URL path, auth header, body shape, and error surfacing) and a live request returning a real 26 KB MP3 through the gateway.
- **Voice browser on media provider pages showed Edge-TTS voices for every provider.** The provider-specific routes (`/api/media-providers/tts/{elevenlabs,inworld,deepgram,minimax}/voices`) carry the provider in the URL path, but `HandleAudioVoices` only read the `?provider=` query — absent on those paths — so its edge-tts fallback answered them all with Microsoft voices (`af-ZA-AdriNeural`…). Upstream serves each path from its own route with the provider hard-wired; the handler now derives the provider from the path when the query is absent. Verified live: the elevenlabs path now returns the account's ElevenLabs voices (Roger, Sarah, Laura…) while the plain `/voices` path still returns the 75-language Edge-TTS catalog.
